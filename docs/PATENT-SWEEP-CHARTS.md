## US 8,458,680 B2: "Systems and methods for dynamically choosing a processing element for a compute kernel"

Independent claims 1 (method), 9 (system) and 17 (non-transitory medium). Their elements are the same; 9 adds "memory" and "at least one program stored in the memory", 17 recites "one or more programs ... executed by a parallel-processing computer that includes multiple types of processing elements using shared memory". One chart covers all three.

**Elements that may be ABSENT, first:** (a) "using shared memory" (E0); (b) "receiving one or more operation requests issued by an application ... at runtime" taken as call-by-call requests (E1, partly). Neither is absent in the general case; both depend on how a court reads the words, and (a) depends on the hardware Fuel runs on. Every other element is present.

| # | claim element (claim 1; 9 and 17 identical in substance) | rating | where in Fuel / why |
|---|---|---|---|
| E0 | "at a runtime system executing at a parallel-processing computer that includes multiple types of processing elements using shared memory" | **partly** | Multiple processing-element types in one process: yes (CPU, CUDA, Vulkan, Metal backends; `fuel-dispatch/src/optimize.rs:245` `optimize_graph`, `fuel-dispatch/src/ranker/placement_dp.rs:1` cross-device placement). **"Using shared memory": not a design property.** Discrete devices have separate memory and Fuel moves data with explicit copies (`insert_residency_copies` in `fuel-dispatch/src/optimize.rs`; `fuel-dispatch/src/residency.rs`). On hardware where the CPU and an integrated GPU share physical memory the words may read; Fuel does not require or exploit it. Whether this preamble phrase limits the claim is a claim-construction question for counsel. |
| E1 | "at runtime: receiving one or more operation requests issued by an application" | **partly** | The application issues operations through the lazy tensor API (`fuel-tensor/src/lazy.rs:980` `matmul`, and the other ops), which build graph nodes; nothing runs until the application calls realize (`fuel-tensor/src/lazy.rs:1929` `realize_f32`; executor `fuel-dispatch/src/pipelined.rs:908` `PipelinedExecutor`). **Overall for '680:** every element is present or present with a construction question (E0, E1). Taken at face value this is a close read, closer than anything else found so far, and it is the core of how Fuel dispatches. **Verdict: `needs-review`** (real overlap on every independent claim that this lane cannot resolve). Not assessed: whether the claims are valid over prior art before 2006-06-20 (kernel libraries chosen per processor, e.g. BLAS dispatch, existed before that date; that is an invalidity question for counsel, not something this chart establishes), whether a licence or Google's patent pledges apply, and what the remaining life (to about 2030-08) means for planned releases.

## Points a lawyer would argue (the PM asked for these to be recorded)

1. **"Using shared memory" ('680 preamble, E0).** Whether the phrase limits claim 1 at all (a preamble is limiting only if the body depends on it or the claim is read to need it for antecedent basis or life and meaning), and, if it does, whether a system whose processing elements have separate memories joined by explicit copies "uses shared memory". Fuel's cross-device copies (`insert_residency_copies`, `fuel-dispatch/src/residency.rs`) are the fact pattern; unified-memory hardware is the fact pattern that cuts the other way.
2. **Call-by-call requests versus a lazy graph ('680 E1, '368 R1).** Whether "receiving one or more operation requests issued by an application ... at runtime" covers a runtime that receives ops one at a time and executes them, or also a runtime that accumulates them into a graph, plans the whole graph, and executes at realize. Fuel's design is the second; the patents' own examples (API function calls, dependent claim 7 of '680) are closer to the first. The argument is about "at runtime" and "receiving", not about whether the planning happens inside the application's process (it does).
3. **"Code reuse section" ('066 P1)** and **"previously compiled ... by the runtime system for the application" ('066 P4)**, as charted above.
