## Ideas swept

Each is a mechanism the project implements or commits to, in claim-like form. "Where" names the design document or code that states it, so a reader can check the sentence against the source. How much of each exists in the tree at the swept commit is stated in the note after the list (ideas 5 and 7 are specified only); the rest are implemented in whole or in part.

1. **Placement that sees every backend's fusion catalog.** A method of running a computation graph across several compute devices in which an optimizer, before assigning operations to devices, obtains from each backend a catalog of the fused operations it can execute with their measured costs, and chooses between "fused on device A" and "unfused on device B" by comparing total cost including the transfer cost of moving intermediate tensors between the devices. Where: `docs/architecture/01-identity.md` edge 1; `04-optimization.md`.
2. **Framework-side fusion strategy, backend-side kernel synthesis.** A loop in which the framework (not the backend) selects which sub-region of the graph to fuse and when, and asks a backend to synthesize one kernel for exactly that region; backends only advertise capabilities and costs and never decide what to fuse. The synthesized kernel is registered as a new fused-operation identity under a cost gate. Where: `01-identity.md` "Backends advertise; they don't decide"; `10-decisions-log.md` 2026-06-20 adaptive runtime fusion (G3/G4/G7); `fuel-dispatch` JIT carrier code.
3. **Algebraic-equivalence rewriting of the tensor graph with one engine for declarative and callable patterns.** Searching the operation graph for rewrites that compress compute or memory traffic (distributivity across matmul, factoring, common-subexpression hoisting across non-trivial boundaries), where patterns are either declarative with variables or callable matchers, run by the same engine. Where: `04-optimization.md`; `fuel-graph` rule engine.
4. **Bounded per-device Pareto frontier of preserved routes, picked at run time.** After optimization the system keeps, per device, a bounded set of mutually non-dominated execution routes ranked by a cost vector (bounded by crowding distance rather than a fixed global count), and a runtime route picker selects among them per request from live telemetry (memory pressure, queue depth, currently loaded weights, request priority) without recompiling. Where: `01-identity.md` edge 3; `04-optimization.md`; `06-runtime.md`.
5. **Per-operation numerical tolerance budgets consumed by the optimizer.** A user, developer or model definition attaches an allowed numerical deviation to an operation or region; the optimizer tracks the cumulative error of each candidate route and prunes routes whose accumulated error exceeds the budget, which unlocks lowering precision, floating-point reassociation, and approximate intrinsics only where the budget allows, while the default remains strict equivalence. Where: `01-identity.md` edge 5; `07-tolerance.md`. (Specified only; see the note after the list.)
6. **Empirical profile-driven dispatch surface.** A "Judge" that measures every (operation, dtype, size class) on every (backend, device) and produces a dispatch table in which measured values override static estimates registered with fused operations, later extended to measure the error contribution of each operation as well as its latency. Where: `01-identity.md` "Cost data is empirical"; `fuel-dispatch` cost and telemetry modules.
7. **Opt-in, anonymized harvest of unfused operation sequences to steer kernel development.** Recording, only when the user opts in, the longest unfused operation sequences and the most frequently repeated sequences from real workloads, anonymizing them and reporting them, so that the next fused kernels are chosen by measured need. Where: `08-pattern-harvest.md`. (Specified only; see the note after the list.)
8. **Recipe principle: every fused operation ships a total, never-panicking decomposition and a pattern.** The set of primitive operations is closed at build time; each fused operation carries a decomposition into primitives that is total (defined for every input it accepts) and a graph pattern; an operation that cannot be decomposed is reported as a gap at build time instead of failing at run time; a checker enforces the property. Where: `CLAUDE.md` "recipe principle (G1/G2/G3)"; `fuel-graph/src/registry`.
9. **Self-describing tensor storage with scale as a sibling operand.** Representing a tensor's logical dtype, its physical storage type and its encoding as three separate descriptors, with quantization scales (and zero points) carried as separate sibling operands rather than embedded in the tensor, so one dispatch path handles block-quantized, affine-quantized and float formats across backends. Where: memory notes "self-describing storage"; `fuel-ir/src/stype.rs`, `quant_scale.rs`; `fuel-quantized`.
10. **Plan-once decode with symbolic extents, and replay of a captured run.** Planning and optimizing an autoregressive decode graph once with symbolic sequence-length dimensions, re-binding the extents per step instead of re-planning, and replaying a captured sequence of device launches (with byte-exact results against the uncaptured run). Where: memory notes "Phase D symbolic extents", "CapturedRun executor"; `fuel-dispatch/src/pipelined.rs`; `fuel-tensor` lazy decode pair.
11. **Paged key/value block pool with prefix sharing, and ragged batched paged decode.** A fixed-size block allocator for attention keys and values with sharing of common-prefix blocks between sessions, and a decode step that batches sessions of different lengths with per-row positional encoding. Where: `fuel-kv-pool`; `fuel-inference/src/multi_session.rs`.
12. **Residency planning by live-range analysis, with evict/reload chains inserted around the best candidate.** Computing from the graph the live ranges and peak device bytes of an execution order, and, when the peak exceeds a device budget, inserting a move-to-host operation and a reload copy around the tensor with the largest product of size and inactive gap, repeating until the graph fits or no candidate remains. Where: `fuel-dispatch/src/residency.rs`; `docs/design-notes/2026-10-25-larger-than-vram.md`. (Wired into the optimizer by PR #498; prefetch ordering and weight streaming are designed, not built.)
13. **Bounded scan operation and data-dependent shapes in a lazy graph.** A single bounded `Scan` primitive that expresses recurrences inside the lazy graph, and shapes that depend on runtime data resolved through a shape oracle at plan time. Where: memory notes "Frontier paradigms", "Data-dependent dynamic shapes"; `fuel-ir`. (Partial.)
14. **Kernel interchange seam with a closed key and an open quantization sidecar.** A seam between a framework and kernel providers in which kernels are identified by a finite published key (structure key) that excludes quantization facts, and quantization granularity, scale placement and block structure travel in a separate open overlay, advertised by capability bits. Where: `fuel-kernel-seam*`; `13-interchange.md`; the FDX-successor design thread with KISS and baracuda.
15. **Cross-vendor multi-device execution in one process.** Executing one graph across devices of different vendors (CUDA, Vulkan, CPU, Metal) with the optimizer inserting cross-device copies at placement boundaries and an executor that orders destructive moves after every non-destructive reader of their source. Where: `fuel-dispatch` `optimize.rs` `insert_residency_copies`, `pipelined.rs` `execution_plan`; the tri-backend live tests.
16. **Lazy-only execution with an explicit realize point, so that the optimizer owns every decision.** No eager path exists; every computation is a graph realized explicitly, so placement, fusion, precision and scheduling are decisions of the graph optimizer. Where: `01-identity.md`, `09-non-goals.md`.

**Not in the list, on purpose:** ordinary techniques Fuel uses but does not claim as its own (flash attention, paged attention as published, GGUF block formats, BLAS/GEMM, tokenizers, CUDA graphs as such, mixed precision as such). A sweep of those would be a freedom-to-operate review of the field, which this record is not.
