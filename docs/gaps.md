# Fuel gap registry

**Every deferred, incomplete, or declined path in Fuel lives here — one greppable list, not scattered across 40 files.** This exists because the JIT launcher's scalar-only limitation was acknowledged in a code comment ("documented loader follow-up") but never on any schedule, so it rotted for months and shipped an all-zero output. A gap acknowledged in prose but not tracked is a leak.

## Rules

1. **Every** `todo!()` / `unimplemented!()` / `panic!(` on a non-test path, and every prose hedge, carries a `// GAP(GAP-NNN)` reference to a row below. **Enforced prose-hedge patterns (GAP-141 inc 2)**, in comments on production paths: `for now`, `not yet`, `doesn't yet`, `shortcut`, `bails`, `would need`, `stopgap`, `workaround`, `naive`, `temporary` (case-insensitive) + `TODO`, `FIXME`, `XXX`, `HACK` (uppercase markers) — **14 patterns**. A new hit fails CI unless GAP-referenced, reworded, or deliberately added to `fuel-ir/tests/gap_hedge_allowlist.txt` (which **may only shrink** — stale entries also fail, so removing a hedge forces removing its allowlist line). `todo!`/`unimplemented!` are enforced by inc 1 (`gap_refs.rs`); **`panic!(` is measured, not yet enforced — see GAP-016.** Baseline at adoption: 648 files, 221 hedges, 216-key allowlist, 0 new, 0 stale.
2. Adding such a path **without** a `GAP(...)` ref is a defect. **Enforcement is incremental and the gap between rule and gate is stated deliberately, because an unenforced rule 1 would be exactly the defect this registry exists to prevent** — see GAP-141. **Increment 1 (ratified 2026-08-07):** `todo!()` / `unimplemented!()` only, 36 sites. **Increment 2 (SCHEDULED, not deferred):** prose hedges via a shrinking allowlist — this is the increment that addresses the founding case, see GAP-141. **`panic!(` is measured but unenforced** pending a gap-vs-invariant policy — see GAP-016.
3. Close a gap → strike its row (`~~GAP-NNN~~ CLOSED <commit>`) and remove the `GAP(...)` ref from the code in the same change.
4. Owners: **A** = launcher / KISS-alignment / FKC-dispatch; **B** = cuda-backend / concurrency / gate; **C** = decode / models / fuel-core; **—** = pooled / unassigned. (Owners are roles, not sessions; claim by editing the row.)

## Tiers (completion order)

- **A — Correctness:** panics on production paths, silently-wrong results, missing gradients, races. Do these first; several violate the "never panic on production paths" hard rule.
- **B — Roadmap commitments / frontier:** architectural work other things depend on.
- **C — Feature completeness:** missing capability that currently **declines cleanly** (typed error / CPU fallback) — honest, lower-stakes.
- **P — Performance:** optimization only; no correctness stake.
