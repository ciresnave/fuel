# Strata: ideas worth experimenting with in Fuel

Requested by CireSnave 2026-10-19: take the ideas from Strata that would benefit Fuel without vastly changing how Fuel is built, and add them to the roadmap as areas to experiment on and likely add. Docs only. Nothing here is started; the candidate rows are in `ROADMAP.md` item 16.

## Method and limits

- One pass, 2026-10-19. Strata read at `Niko1221/Strata@e88ee39d1d6be6e3364183af3b39b62a7ed6f211` (README, `docs/*.md`, `bench/results/*`). **The C++/CUDA source was not read**: every mechanism below is as the project's own documents describe it. Fuel facts are read from `origin/main` at `9d0f97066467d5219e4a17c22602fadf957413e6` with `git show` / `git grep`.
- **Every Strata speed figure is the project's own**, on a few named machines (RTX 3090 + EPYC, 2x modified RTX 3080 20 GB, RTX 2080 Ti, RTX 3060, RTX 5070). Several of its docs say the historical timings were not re-measured on current main. No number here is a Fuel measurement; each is a hypothesis to measure.
- Strata is a single-model engine: a ggml/llama.cpp-derived runtime built around Qwen3.8-Flash-Next (125B-parameter mixture of experts, 24,576 experts, 10 active per token, hybrid DeltaNet/attention, built-in MTP draft layer, a 28.8 GB n-gram table). Its tricks are tuned to that shape. A dense model gains little from S1, S2 and S10.
- Scope rule applied: `docs/architecture/09-non-goals.md`. Foundation holds mechanism; orchestration and policy (batching, admission, serving loops, session lifecycle) live in `fuel-inference` or a consumer. Each row says which side it lands on.
- Provenance: ideas are free to take; **copying Strata or ggml files needs their notices** (`THIRD-PARTY-NOTICES.md`). Strata credits Splash, ninfer and HyperQwen for some of its ideas.

## What Fuel already has (so the rows do not re-propose it)

From `origin/main` at `9d0f97066467d5219e4a17c22602fadf957413e6`, positive controls in brackets:
- Sparse-MoE by data-determined shapes (`NonZeroIndices` per expert, capacity buffers) in `fuel-graph/src/lib.rs`; DeepSeek-V2 MoE in `fuel-transformers/src/models/lazy_deepseek2.rs`; indexed-MoE forward on CUDA only in `fuel-backend-contract/src/quantized.rs`.
- Draft-model speculative decoding in `fuel-model-llama/src/lib.rs` (`spec_argmax`). **No MTP-head support**: `git grep -l -E 'MtpHead|multi.token.pred|mtp_'` finds 0 files (the same query style finds `spec_argmax` in 2).
- KV block pool (`fuel-kv-pool`, not yet consumer-wired), prefix-sharing serving (rung 1), `DecodeSession` persistent decode, residency/eviction code in `fuel-dispatch`, streaming route pick (`OrderSource::Streaming`).
- Judge (measured backend ranking) and fusion telemetry.

## Candidate rows

`Mech` = Foundation mechanism; `Policy` = lands above Foundation. Cost: S under a week, M weeks, L a program. Every row needs a PM ruling before it starts.

| # | Idea | What Strata does (source) | Fuel mapping | Cost | Experiment |
|---|---|---|---|---|---|
| S1 | **Sub-tensor expert residency: hot experts in VRAM, all experts in pinned RAM, CPU computes the rest concurrently** | GPU keeps dense parts plus an expert cache that fills spare VRAM; RAM holds every expert; the CPU runs uncached experts in place at the same time as the GPU runs cached ones. "Every extra GB holds ~700 more experts" (`docs/HOW_IT_WORKS.md`) | Mech: residency below tensor granularity (a per-expert slot table over one stacked weight tensor) + a CPU/GPU `Op::Branch` split for the grouped expert matmul. Policy: which experts are hot (S2). Needs a design note first; the largest change in this list | L | Qwen3-MoE-class model that does not fit in 12 GB. Metric: decode tok/s vs full-CPU and vs layer-offload at equal VRAM; tokens bit-identical to the all-GPU run |
| S2 | **Routing-telemetry-driven expert placement with a shipped cold-start profile** | Adaptive tier moves experts between RAM and VRAM by decayed routing counts; ships `expert-profile*.bin` as the starting set and can save the learned set. Its own measurement (Intel Arc Pro B70, SYCL path): a profile learned on code speeds code +13–19% and slows prose −18%, so one file per kind of work (`docs/DETAILS.md`) | Policy over Fuel's existing telemetry/Judge. Mech: a routing-count counter surfaced by the grouped-expert op | M | Replay a routing trace against the placement policy offline (Strata ships `tools/replay_cache_policy.py` for this) before any device work. Metric: modelled hit rate vs cache size |
| S3 | **Self-drafting from the model's own MTP head, plus cost-gated prompt-lookup drafts** | Model's MTP layer drafts up to 3 tokens, one pass over all layers verifies; 2.4–3.2 tokens per pass; prompt-lookup drafts (up to 5) only where measured acceptance and cost say it pays. Output is the target's (`HOW_IT_WORKS.md`) | Mech: MTP head as part of a model definition (a few extra graph nodes) and a verify-window decode path. Policy: draft length and gating. Builds on `spec_argmax` | M | Metric: tokens per verify pass and wall tok/s vs no-draft, output bit-identical under greedy |
| S4 | **Verify-window grouped expert kernels with activations staged in shared memory, shipped with a bit-identical bench** | `EXPDEC` and `QSA_ROWS`: opt-in kernel variants that stage a group's rows in shared memory and keep queries in registers; each ships a micro-bench that memcmp's against the default kernel and exits non-zero on any difference (`docs/EXPDEC.md`, `QSAROWS.md`) | Mech: a FusedOp recipe for grouped expert FFN with backend kernel bindings (baracuda is a dependency we do not modify; Vulkan side is fuel-internal Slang). The *bit-identical-variant bench* is the transferable part and fits `07-tolerance.md` | M | Gate: variant output equal bit for bit on every cell; metric us/call at T=1..4 |
| S5 | **Overlap next layer's weight/KV upload with the current layer's compute** | Prefill streams the next layer's experts over PCIe while attention runs; `STRATA_KV_PREFETCH` does the same for KV in RAM. Own measure: prefill −4–5% at 32–64K, no decode gain (`docs/KV_PREFETCH.md`) | Mech: a second-stream prefetch edge the optimizer adds to the plan; fits "plan is the graph". Expect small, workload-specific wins | S–M | Metric: prefill time at 32K/64K with KV partly in RAM; honest prior is single-digit percent |
| S6 | **Time-share lifetime-disjoint buffers across phases** | Output head's VRAM lent to prefill buffers (`--prefill-head-alias`): prefill chunk 768 → 2,048 tokens on an 8 GB card, prefill 387 → 667 tok/s (own measure, `docs/PREFILL_HEAD_ALIAS.md`) | Mech: liveness-based buffer aliasing in the planner; the graph already knows each node's lifetime. The cheapest row here | S | Metric: max prefill chunk and prefill tok/s on an 8 GB card, with and without aliasing |
| S7 | **Partial KV residency with block-level selection for very long context** | From 64K tokens only the most-read part of KV stays on GPU, the rest streams from RAM; the model's own indexer picks top-k key blocks (`QSA_ROWS`) | Mech: `fuel-kv-pool` block addressing + a block-score op. Blocked on the pool being consumer-wired | L | Metric: decode tok/s and needle-in-haystack accuracy at 128K–262K on a fixed VRAM budget |
| S8 | **Checkpoint recurrent/prefix state at turn boundaries and near the prompt tail** | Saves one checkpoint before the final short user message (and near the prompt tail) so an edited last message does not reread history; own measure first-edit −33% (combined with a chunk-size change, so not attributable) (`MESSAGE_BOUNDARY_CACHE.md`, `PROMPT_CACHE_TAIL.md`) | Mech: snapshot/restore of decode state including `Op::Scan` carry states. Policy: where to checkpoint (fuel-inference prefix serving) | M | Metric: time-to-first-token on an edited-last-message agent trace |
| S9 | **File-backed row-gather for a huge lookup table** | The 28.8 GB n-gram table stays on SSD, a few rows read per token through the OS page cache | Mech: a file-backed storage kind for row gather. **Blocked on GAP-204** (safetensors loading copies the mmap) | M | Metric: tok/s with the table on SSD vs in RAM; RAM saved |
| S10 | **KL-divergence-vs-bytes as the quant admission metric, with a measured self-noise floor** | Compares quants by KL on 128 text chunks at equal GPU bytes (Q2_0 0.312, Gyro-M 0.159, IQ3_XXS 0.157), and reports the engine-vs-itself floor (0.0006–0.0007) so differences below it are not claimed (`docs/GYRO.md`, `DETAILS.md`) | Policy input to `07-tolerance.md` and `fuel-quantized` (GAP-211): a quality number per quant that a tolerance budget can cite, plus a run-twice noise floor for Judge/tolerance tests | S | Metric: KL per quant on a fixed corpus; floor from two identical runs |
| S11 | **Rotation-basis and trellis quant families (Gyro `TQ2_T`/`TQK6`/`TQK7`)** | Hadamard-rotated, trellis-coded expert blocks; decodes ~20% slower than Q2_0 on 12 GB cards but halves KL at equal GPU bytes (own measure) | Mech: new `DType`/`SType` decode types after GAP-211's decode-only policy; the rotation is expressible as a recipe on activations. **Quantizers and on-device matmul for decode-only types stay PM-gated** | L | Only after GAP-211 leftovers are ruled; Metric: KL vs bytes (S10) and tok/s |
| S12 | **Disjoint expert ownership across multiple GPUs** | Option keeps helper-GPU experts out of the primary cache's promotion candidates; ~1,900–2,000 duplicate slots observed; generation 81.5 → 94.1 tok/s historically (`DISJOINT_EXPERT_CACHE.md`) | Policy constraint inside S1/S2 placement, not a separate project | S (after S1) | Metric: duplicate slot count and tok/s on 2 GPUs |
| S13 | **Elastic VRAM: give cache segments back to another program on request** | Expert cache allocated in segments; `POST /v1/vram` unmaps trailing segments (NVIDIA only; `VRAM_ELASTIC.md`) | Mech: segmented cache allocation + a release hook. The HTTP route is serving policy and is out of scope | M | Low priority; only if a consumer needs GPU sharing |

## Rejected or deferred

- **HTTP OpenAI/Anthropic API server, MCP server, desktop app, one-click installers, Docker images, Grafana dashboards**: serving engine and packaging; `09-non-goals.md` places these above Foundation.
- **Batched DMA submission (`cudaMemcpyBatchAsync`)**: Strata's own doc calls it "an experiment to reduce host submission overhead, not a demonstrated increase in model tokens per second". Revisit only if S1 shows submission overhead in a profile.
- **Exchange-buffer rotation** (`STRATA_EXCHANGE_ROTATE`, avoids one host memcpy on expert swaps; +5.2% decode on one card, +1.4 GiB pinned RAM): an implementation detail of S1; decide inside that design.
- **Single-model hard-coding** (kernels fixed to one model's n_embd/n_ff): Fuel's recipe principle is the opposite; take the technique, not the specialization.
